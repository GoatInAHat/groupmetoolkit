# Groupmetoolkit — OpenClaw plugin

Generated by toolfactory from `plugin.json` and `dev.toolfactory/ops.json`.
The layout is whatever `openclaw plugins init --type tool` writes; the tool list, the manifest
contracts and the entry between the `tf:entry` markers in `src/index.ts` are projected.

## Build

```bash
npm install
npm run plugin:build
npm run plugin:validate
npm test
```

`.npmrc` sets `install-links=true`. OpenClaw's install-time safety scan refuses a
`node_modules` symlink whose target lies outside the install root, which is what npm makes of a
`file:` dependency such as the core package in `package.json`; with `install-links` npm
materialises it as a real directory and `openclaw plugins install --link` succeeds.

## Install into a live OpenClaw, and remove it again

```bash
openclaw plugins install --link hosts/openclaw --force --accept-capabilities
openclaw plugins inspect groupmetoolkit --runtime --json
openclaw plugins disable groupmetoolkit
```

`--link` registers this checkout in place rather than copying it (a copy takes
`node_modules/openclaw` with it), so the plugin's origin is a config entry and
`plugins disable` is what removes it again, leaving the checkout untouched.
`openclaw plugins uninstall groupmetoolkit --keep-files` is the equivalent for a
plugin installed as a package; against a linked checkout it reports conflicting registry rows
and changes nothing (openclaw 2026.8.2).

## Tools

- `chats` — List the authenticated user's direct-message conversations from the documented GroupMe /chats index, with pagination. Returns page, perPage, a count and the projected chats (other_user and last_message). perPage echoes only a caller-supplied per_page and is 0 when omitted: the API documents no default and no total, so no effective value is guessed. Deliberately no total, hasMore or nextPage. (native)
- `group` — Return one GroupMe group by numeric id. An unknown id surfaces a redacted not_found error; the payload is projected to the declared group shape. (native)
- `group_messages` — Read one page of a GroupMe group's message history: projected message ids, timestamps, author names, text and attachments. Supply at most one cursor (before_id = older history, after_id = immediate newer, since_id = newest only); limit is clamped to the official max of 100 (default 20). Pagination metadata is direction-scoped: endOfHistory is only claimed for before_id/latest pages on upstream 304 or a short page, and a non-advancing cursor stops with progressGuardTripped. Nothing is persisted. (native)
- `groups` — List the authenticated user's GroupMe groups with pagination. Returns the validated page/per-page echo, a count, and the projected groups. Deliberately no total or hasMore: a bare-array index has no total, and a full page only implies an unknown next page, never a confirmed one. (native)
- `me` — Return the authenticated GroupMe profile: id, name, avatar URL, and timestamps. Phone number and email are never returned. (native)
- `search_group_messages` — Search one GroupMe group's message history for a case-insensitive text substring. GroupMe v3 has no server-side search, so this is a client-side bounded scan: it pages backward with before_id, examines at most `budget` messages (clamped to 500, default 100) in pages of `limit` (clamped to 100, default 20), and stops when it has `maxMatches` matches (clamped to 100, default 25). Returns scanned/matched/pagesFetched with truthful metadata: endOfHistory is true only on upstream 304, an empty page or a short page, never when the budget or match cap stopped the scan; warnings names exactly why it stopped (budget_exhausted, match_cap_reached, progress_guard_tripped) and nextBeforeId is the last examined message id, so a continuation never skips unexamined messages. Matches only message text; attachment-only messages never match. Nothing is persisted. (native)
